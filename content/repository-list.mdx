# Repository List

The **Repository List** is FinderGit's home. Instead of drilling into one folder at a time, it shows **every repository you track in a single flat, sortable table** — branch, status, sync state, file count and size, side by side. The left sidebar slices that list by status or remote host, and a summary bar along the bottom keeps the whole picture in view.

![The Repository List — a flat table of every repo, with the status sidebar and the summary bar](/screenshot-portfolio.png)

On macOS 27, pull down from the top of the repository list to run the same update as **Refresh** or <Kbd>⌘</Kbd> <Kbd>R</Kbd>. The gesture is also available in Favorites, Recents, smart views and provider filters, including an empty filtered list. The spinner holds for at most two seconds; updates continue in the background.

## The sidebar

The sidebar is the control panel for the list. Picking an entry changes *what the table shows*; it's organized into five sections.

### Collapsing and hiding

**Library**, **Smart Views**, **Filters** and **Root Folders** collapse and expand from their header: hover the header and click the chevron, as in the Finder. Each section remembers its state across launches. Dropping a folder on the sidebar while **Root Folders** is collapsed opens it, so the new root is in view.

Rows you never use can leave the sidebar altogether: right-click **Favorites**, **Recents**, a Smart View or a Filter and choose **Hide from Sidebar**, or click its tile in [Settings → Appearance → Sidebar](/docs/settings#sidebar), which is also where a hidden row comes back. Hiding a row takes nothing out of **All Repositories** or the dashboards; it only declutters the sidebar. A section with every row hidden disappears, header included, and if the row you were on is hidden, FinderGit shows **All Repositories** instead.

### Dashboards

The four global dashboards, pinned at the top:

- **[Overview](/docs/overview)** — an aggregate dashboard across every repository (clean/dirty/unpushed counts, disk usage, a "needs attention" list).
- **[Account](/docs/account)** — your GitHub profile, stat tiles, and contribution graph.
- **[Cleaning](/docs/cleaning)** — the space your developer tools can rebuild on their own, from `node_modules` to package caches, and the button that frees it.
- **[Agents](/docs/agents)** — what your coding agents read before they start, what it costs, and the fixes it needs.

### Library

- **All Repositories** — every repo you track, the default landing view.
- **Favorites** — repos you've starred for quick access (see [Favorites & Recents](#favorites--recents)).
- **Recents** — the repositories you opened most recently, newest first.

Each row carries a live count.

### Smart Views

Dynamic, status-driven filters — each shows a running count and updates in real time as your repositories change. No setup; they read the Git status FinderGit already computes for every repo.

- **Changes** — repos with uncommitted changes in the working tree.
- **Ahead** — repos with local commits to push.
- **Behind** — repos with upstream commits to pull.
- **Diverged** — repos where both sides moved on: neither a pull nor a push works until the branch is reconciled with a merge or a rebase. They also count under Ahead and Behind; this view calls them out because they need a decision rather than a click (see [When your branch has diverged](/docs/git-actions#when-your-branch-has-diverged)).
- **Dirty** — anything that isn't pristine: uncommitted changes *or* an out-of-sync branch.
- **Clean** — fully in sync: working tree matches HEAD and the branch is level with (or has no) upstream.

![The Smart Views section filtering the list to repositories that need attention](/screenshot-smart-views.png)

**Behind** and **Ahead** can be settled in one click. A strip above the table counts what is ready — *3 repositories ready to pull* — and its **Pull All** runs a [bulk pull](/docs/git-actions#bulk-actions-across-repositories) on every one of them; in Ahead the button is **Push All…**, which asks before it pushes. Diverged repositories sit in both views and are left out, and the strip says how many: a merge or a rebase is a choice for you to make, one repository at a time, from the **Diverged** view.

![The Behind view with a strip above the table: "1 repository ready to pull · 1 diverged, left out", and a Pull All button on the right](/screenshot-fleet-pull-all.png)

### Filters

Group the list by where each repository's `origin` remote points:

- **GitHub**, **GitLab**, **Bitbucket**, **Codeberg** — recognized from the remote URL.
- **Local Only** — repositories with no recognized remote.

> Live forge data (Issues, PRs, Stars, and a fork's parent) is populated for **GitHub**, **Codeberg**, **GitLab** and **Bitbucket** remotes — the last three with no setup at all, since their APIs answer anonymously. Two caveats: only GitHub reports **how far** a fork trails its upstream, and Bitbucket has no issue tracker any more, so its Issues column stays empty. See [GitHub Integration](/docs/github-integration).

### Root Folders

The directories you've added for scanning, plus the Tower-style **groups** you organize them into. Selecting a root folder (rather than a Library/Smart View entry) switches the main area to the **[File Browser](/docs/file-browser)** — the Finder-style tree, for drilling into that folder's files. Adding, removing, reordering and grouping roots is covered in [File Browser → Root Folders](/docs/file-browser#root-folders).

### Nested repositories

By default FinderGit counts the **outermost** repository on each path: if a root folder is itself a Git repository, the scan stops there. When a "container" repo holds independent clones inside it — a folder of related projects that also happens to be under version control — those inner repositories aren't counted.

Turn on **Discover nested repositories** to also count the repositories nested inside a repository. It's off by default and available three ways: Settings → General → File Browser, the **View** menu (<Kbd>⌘</Kbd> <Kbd>⇧</Kbd> <Kbd>N</Kbd>), or a toolbar toggle next to Refresh. The difference is immediate — here a `workspace` repository holds an independent clone at `packages/parser`, and the list goes from 15 to 16 repositories:

![All Repositories with nested discovery off — 15 repositories, the workspace container among them](/screenshot-nested-off.png)

![All Repositories with nested discovery on — 16 repositories, now including the parser clone nested inside workspace](/screenshot-nested-on.png)

The file browser always lists the nested repositories in the tree, each with its own branch and status; the toggle only controls whether they feed the counts, the Smart Views, and the Overview. It stays bounded by your [scan depth and excluded folders](/docs/settings#file-browser), and submodules are never counted.

![The workspace repository expanded in the file browser, its nested parser clone showing its own branch and status](/screenshot-nested-tree.png)

### Linked worktrees

A checkout created with `git worktree add` is counted as a repository of its own. Keep it beside its checkout — `myproject` and `myproject--feature` under the same root folder — and both appear in the list, each with its own branch, status and ahead/behind.

The distinction is the same one nested repositories have: the **file browser** always showed a worktree in the tree, while the list, the Smart Views and the Overview did not count it. Now they do.

A worktree keeps its git state in two places — its own folder holds `HEAD` and the index, while refs, objects and the stash stay with the main checkout — and FinderGit follows both, so:

- **Live updates reach it.** Commit, switch branch or fetch from a terminal inside the worktree and the row updates in place, even though those changes land in the main repository's folder rather than the worktree's.
- **The stash is the repository's.** `git stash list` shows the same entries from every worktree, and so does FinderGit: the Stash section is there whichever one you open.
- **Sibling worktrees stay out of each other's way.** A dozen worktrees on one repository do not refresh each other.

The **Size** column shows what that worktree occupies — tens of kilobytes, since the history is shared with the checkout — not the repository's full history.

## The table

<Tutorial n={2} />

One row per repository. Every column is sortable — click a header to sort, click again to reverse.

- **Repository** — icon, name, and home-relative path (`~/Projects/App`). A ⭐ marks favorites.
- **Branch** — the current branch.
- **Status** — a pill: green **Clean**, or orange **N changes** when the working tree is dirty.
- **Ahead/Behind** — **↑ ahead N** / **↓ behind N** relative to upstream, **↑N ↓N** when the branch has diverged, or **—** when in sync.
- **Files** — number of tracked files (`git ls-files`).
- **Size** — the repository's Git-data footprint on disk (see [Repo Maintenance](/docs/repo-maintenance)).

Selecting a repository reveals the **[Detail Panel](/docs/detail-panel)** beside (or below) the table — the same one-page panel with a card for each section, and the docked Fetch / Pull / Push / Stash… / Refresh actions. **Double-click** a row (or **Browse Files** from its context menu) to open that repository in the [File Browser](/docs/file-browser).

### Selecting several repositories

⌘-click or ⇧-click to select more than one row, or <Kbd>⌘</Kbd> <Kbd>A</Kbd> to select them all. The panel then becomes the selection's summary: how many, their clean / dirty / ahead / behind tallies, and **Fetch**, **Pull** and **Push** for the whole group, run as a [bulk action](/docs/git-actions#bulk-actions-across-repositories). Right-click the selection for the same three, plus **Reveal in Finder**.

A row that leaves the view leaves the selection too: after a bulk pull in **Behind**, the repositories that caught up are gone from the list, and from what the next button would act on.

![Three repositories selected in the list, and below it their summary: 3 Repositories Selected, the tallies, and Fetch 3 Repos, Pull 3 Repos, Push 3 Repos](/screenshot-fleet-selection.png)

### Row actions

Right-click any row for: **Add to / Remove from Favorites**, **Browse Files**, **Open in Finder**, **Open in Terminal**, **Open on GitHub** (or GitLab / Bitbucket / Codeberg — the label follows the remote's host), and **Fetch / Pull / Push**. On a diverged repository, **Pull** is replaced by **Pull with Merge** and **Pull with Rebase**.

## Favorites & Recents

- **Favorites** — right-click a repository → **Add to Favorites** (or use the ⭐). Favorites get their own Library entry so the repos you touch daily are always one click away.
- **Recents** — populated automatically as you open repositories, newest first — no bookkeeping.

Both lists persist across launches.

## The summary bar

A bar along the bottom of the list keeps the workspace total in view at all times:

**N repositories · ✓ clean · ● dirty · ↑ ahead · ↓ behind · Total size**

A **diverged** count joins them whenever at least one repository has diverged — it stays hidden at zero, so when it appears it means something. The counts and total size are live — they track the same status data the Smart Views count, so the bar always agrees with the sidebar.
