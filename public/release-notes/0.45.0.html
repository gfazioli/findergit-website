Release notes

FinderGit 0.45.0 — The Overview tab becomes a dashboard of the repository

Highlights

  • A dashboard for every repository. Select one and the Overview tab now tells its story at a glance, where it used to show a description and a few avatars. Most of it is read from the repository itself, so a local-only repository gets it too.
  • Its pulse at the top. How alive it is (Active, Steady, Quiet or Dormant, from its newest commit), when its history began, its latest tag and how many commits sit on top of it. The headline is the forge's description or, when there is none, the opening sentence of the README. Beside it, the commits of the last 30 days over a 26-week line.
  • A tile for every count, and each one is a door. Changes, Stashes, Commits, Upstream, Branches, Worktrees, Tags, Issues, Pull Requests, Stars, On Disk and Findings. Each tile wears the color and icon of its tab and opens it with a click.
  • A year of activity. The last year as a calendar, one square per day, with the current and the longest streak; hover a day to read it. Beside it, the same commits by weekday and hour, with the busiest day and the peak hour.
  • What it is made of. The languages by size, and whether the repository carries a README, a license, a .gitignore, a contributing guide, a security policy and CI.
  • The latest commits and releases as two timelines, with how often a release ships and how many commits are still unreleased. A row opens the Commits or Release tab.
  • Who wrote it. A leaderboard with bars when more than one person did; a solo project is named at the top instead.
  • It moves like the rest of the app. The cards land one after another and the charts draw themselves when you open the tab and each time you refresh it. Nothing moves on its own after that, and with Reduce Motion on everything is simply there.
  • It keeps up. A commit, a pull, a checkout or a new tag updates it, and the calendar moves on to the next day at midnight.

Under the hood

  • One local read per HEAD. rev-list --count, the root commits, log --since for the calendar, shortlog -sne for the authors, ls-tree -r -l -z for the languages and the essentials, describe --tags and the README, run side by side off the main thread and cached per HEAD and per day.
  • Calendar days are calendar days. Days are counted with the calendar rather than in 86,400-second units, so a commit just after midnight stays on its day across a daylight-saving change.
  • Contributors from history. The count comes from local history: GitHub's list is a single page and leaves out authors without an account, so it supplies the faces only when it covers everyone. A GitHub noreply address gives the login, and with it the avatar, without an API call.
  • Languages the way GitHub draws them. Names and colors follow the forge's own language bar; data files, vendored folders and minified bundles are left out.
  • No storm in the Fleet view. A short pause before any git read means arrowing through a list of repositories starts nothing for the ones you pass.

Install

  1. Download FinderGit-0.45.0.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
