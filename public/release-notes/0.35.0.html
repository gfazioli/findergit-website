FinderGit 0.35.0

Release notes

FinderGit 0.35.0 — Stash, where you actually reach for it

Three issues on one small panel, and they turned out to be one decision: where the stash action lives, and what a row's buttons are allowed to act on.

Highlights

  • Stash… has moved to the bar at the bottom, beside Fetch, Pull and Push. It belongs with them because it does what they do — it acts on the whole repository, staged work included. Where it used to sit, in the header above the unstaged files, it stopped existing the moment you pressed Stage All, which is exactly when setting everything aside is what you want. And under a directory filter that header read “Unstaged Changes (4) in src/” while the action took the entire repository; the dialog now states the scope outright instead of contradicting the heading two inches to its left.

  • Stashing says what it is doing, and can be stopped. The button reads “Stashing…” while it runs and turns into Stop after the same few seconds Fetch uses. Pop, Apply and Drop report above the rows rather than inside the list, so an action stays readable even if you collapse the list while it is running — those three had no progress and no way out at all before this. On a clean tree the button says so in its tooltip rather than after the click.

  • The stash list keeps itself current. Refresh in the toolbar now reaches it, and so does a stash you make in a terminal. Before, the list was read once per panel and noticed a change only when a separate count happened to move — and that count comes from a file which, in some repository layouts, cannot be read at all. The list itself now decides whether the section exists, so it no longer depends on a second source that can be blind.

  • Pop, Apply and Drop act on the row you clicked. A stash is identified by its own commit now, not by its position. Positions renumber the moment anything is removed, so a list read a moment earlier could aim a button at a different stash than the one under it — and because the changes applied looked plausible either way, nothing on screen would have said so. If the entry you picked has been applied or dropped elsewhere in the meantime, FinderGit tells you instead of acting on whatever took its place.

Fixed

  • Stash… was unreachable in the one state where you most want it: immediately after Stage All, when the header holding it is no longer drawn.
  • The stash confirmation described a scope narrower than the action's. It takes the whole repository, untracked files included, whatever filter the panel is showing.
  • The stash panel did not survive a repository opened as a linked worktree in every case: the badge that decided whether to draw it could answer zero where git lists the entries perfectly well.

Under the hood

The list is now a per-repository store like every other data source in the app, so one fetch serves every panel showing that repository, a re-listing that finds nothing new does not disturb an open disclosure group, and the toolbar Refresh and file-system events both reach it.

The interesting part was the review. Five consecutive findings were the same defect wearing different hats — a drop that renumbered the rest, a view parked on another tab while the list moved, a refresh still in flight behind live rows — and each fix closed one window while a sixth appeared. The question that ended it was not where is a check missing but which decision here is made on data nobody validated, and the answer was the index itself. Verified by disabling the fix and watching the tests: a Pop aimed at a vanished stash reported success after applying the survivor's changes and destroying the entry that held them.

A sixth round then found that a commit does not identify a reflog entry either. The stash reflog refuses a duplicate only at its tip, so the same commit stored from lower down becomes a genuine second entry — measured, not assumed. The row's own position is therefore preferred whenever it still holds the expected commit, and relocation by commit is the fallback it was written to be.

One pre-existing defect found while reviewing has been filed rather than folded in, and a defect in the screenshot pipeline itself was fixed: two hand-maintained lists of which captures need a tall panel had drifted apart, so one recipe photographed a short one and reported success.

Install

Download the DMG below, drag FinderGit to Applications, and open it. The app is signed with an Apple Developer ID and notarized by Apple, so no Gatekeeper bypass is needed. Existing installs update themselves.

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
