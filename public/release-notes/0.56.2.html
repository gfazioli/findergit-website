Release notes

FinderGit 0.56.2 — Quieter in the background

Highlights

  • Less work while other tools are busy. A repository that keeps other projects inside its own folder, such as a workspace that holds its clones, used to check itself again every time a file was saved in one of those projects, although nothing it shows could have changed. FinderGit now asks once whether the project is part of the repository around it, and skips that check when it is not. With a file saved every two seconds inside such a project, FinderGit ran about a third of the git commands it did before, and its CPU use fell from 3.7% to about 2%.
  • A lighter file browser. An open folder refreshes without rebuilding the rows that did not change, so a folder whose neighbours keep changing costs far less: about a third of the CPU in the same kind of test.

Under the hood

  • A change inside a nested checkout that the surrounding repository does not track now refreshes only the file list: no status check and no refresh of the branch, stash and tag lists. Submodules and repositories added to the index keep their full refresh, and a project that starts being tracked gets the changes it made in the meantime handed back.
  • A folder refresh compares the listing first and builds a row, with its icon and file details, only for an entry that is new.
  • Measured on release builds against 0.56.1: every view still idles at 0.0–0.1% CPU.
  • Translated into Italian, French, German and Spanish.

Install

  1. Download FinderGit-0.56.2.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
