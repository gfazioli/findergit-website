FinderGit 0.34.1

Release notes

FinderGit 0.34.1 — a popover that fits, and controls that mean what they show

A patch over 0.34.0, from using it: one thing that ran off the screen, one set of controls that stayed live when they could do nothing, and a rule this project believed about SwiftUI that turned out not to be true.

Fixed

  • The recent-stars list no longer runs off the screen. FinderGit keeps up to fifty "this repo gained a star" events, and the popover behind the Stars tile drew every one of them at once — so after a busy week it was taller than the display, clipped at both ends, with the rows at the bottom simply out of reach. Measured on the account that reported it: fifty events, about 2000 points of content in a window around 1100 tall. It now stops at a readable height and scrolls.

  • During a bulk tag run, the controls that cannot act say so. Fetch, New Tag and the per-row ⋯ menu were gated on a flag that only single-row actions set, so a bulk run left every one of them live. Worse, a confirmation dialog opened before a run started would still fire afterwards — the identity of the repository was re-checked at that moment, its state was not. Nothing was ever corrupted (every mutation for a repository already goes through one queue), but an action you asked for could sit waiting a minute with nothing on screen explaining why.

Under the hood

The two gates are now one derived predicate rather than two flags that could disagree. The obvious alternative — setting the "busy" flag when a run starts — is the trap: a one-tag action finishing mid-run clears it unconditionally and would unlock everything while the run carried on. Two owners of one boolean was the bug underneath.

And a correction worth making in public, because it is the kind of thing that propagates. 0.34.0's Activity panel shipped clipped to its header; the repair changed two things at once and credited one of them, generalising it into a rule — that a scroll view has no height of its own and reports nothing to its container. Every popover fixed since has cited that sentence, including the first draft of the fix above.

It is not true. A probe that puts each shape into the sizing path a popover actually uses reports the same height with the modifier and without — two rows and forty, lazy and plain. What does the work is the maximum height; the modifier credited for it changes no number at all. The probe is now part of the repository, so the next time a popover is the wrong size the answer comes from running something rather than from remembering a sentence. The comments that stated the wrong mechanism have been corrected, and an issue filed on the strength of it has been closed with the measurement.

Install

Download the DMG below, drag FinderGit to Applications, and open it. The app is signed with an Apple Developer ID and notarized by Apple, so no Gatekeeper bypass is needed. Existing installs update themselves.

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
