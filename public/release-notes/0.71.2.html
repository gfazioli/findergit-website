FinderGit 0.71.2

Release notes

FinderGit 0.71.2 — SSH host aliases, and each contributor once

Bug fixes

  • A remote behind an SSH host alias is read as the repository it points to. Two accounts on one forge are usually kept apart with a Host alias in ~/.ssh/config (Host github-work, HostName github.com) and a remote such as git@github-work:org/repo.git. git reaches GitHub through it; FinderGit compared the alias itself, found no forge it knew, and treated the repository as having no remote at all: the Overview said Local only beside a Commits card In step with origin/main, the Issues, Pull Requests and Stars columns stayed empty, and the repository sat under Local Only in the sidebar. FinderGit now asks ssh what the alias stands for, as git does, so the same remote is a GitHub, GitLab, Bitbucket or Codeberg one in FinderGit too.
  • A remote on a server FinderGit doesn't read is named in the Overview. A self-hosted server used to read Local only, exactly like a repository with no remote. Its Overview now shows the server's name, with a tooltip saying everything there is read from the repository itself, and Local only is kept for a repository that has no remote.
  • A remote written with another user than git@, or with none (github.com:owner/repo), is recognised as well, as git accepts it.
  • The Overview's Contributors list each person once, without stray quotes. A name set with typographic quotes (git config user.name “Ada Lovelace” in a shell stores just “Ada, since the shell sees no quoting there) showed up as “Ada, with a “ for initials, and the same person appeared again under their full name from the same address. Lines that share a name or an address are now one person, shown under the fuller name, and the commit lists drop the stray quotes too. The commit lists also follow the repository's .mailmap now, as Contributors already did.

Under the hood

  • The host behind an alias comes from ssh -G, which prints the configuration ssh would use without connecting, after Include, wildcards and Match blocks: ssh's own answer, not a second reading of its file. It is asked exactly what git would hand it: the alias as written, since Host patterns are case-sensitive, and the remote's user, which a Match user block reads.
  • Only an SSH remote on a host FinderGit doesn't know is looked up; an HTTPS remote or one on a known forge never starts ssh. One lookup per alias, shared by every repository on it and kept for a minute, bounded at 3 seconds; a lookup that fails is not remembered as "no alias". The host and user come from a repository's own configuration, so both must be plain names and the host is passed after --.
  • git trims ASCII quotes from the ends of a name or an address when it writes a commit, never typographic ones; FinderGit now drops quote marks at the ends when it shows one, without touching what git stores. Contributors are grouped by shared name or address, however long the chain, the way a forge ties an address to one account; the commit log reads the author as %aN/%aE.

Install

  1. Download FinderGit-0.71.2.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
