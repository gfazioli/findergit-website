FinderGit 0.56.8

Release notes

FinderGit 0.56.8 — a security update

Highlights

  • A repository you open can't run code while FinderGit reads it. FinderGit looks at your repositories on its own, and a repository could tell git to run a program of its own during that read — so opening one you didn't create could run its code. FinderGit now turns that off.
  • More hardening throughout, including the updater and keeping your sign-in tokens out of caches on disk.

Under the hood

  • Every git invocation now passes -c core.fsmonitor=false, so a repository's configured core.fsmonitor program never runs during the automatic status / ls-files / fetch FinderGit performs on your repositories. The remaining repo-config execution surfaces (clean/smudge filters, hooks, a remote's uploadpack / sshCommand) are tracked in #375 for a trust gate.
  • The Hardened Runtime's disable-library-validation exception is removed: Sparkle is signed with the app's own Developer ID team, so library validation already admits it. release.sh now reads the signed app back and refuses one carrying disable-library-validation or get-task-allow.
  • The GitHub API session no longer uses a caching URL configuration, so an authenticated response can't leave the bearer token in the on-disk URL cache.

Install

  1. Download FinderGit-0.56.8.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
