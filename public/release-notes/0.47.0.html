FinderGit 0.47.0

Release notes

FinderGit 0.47.0 — Make it look your way

Highlights

  • A new Appearance pane. Settings now has Appearance, right after General, with everything that changes how FinderGit looks without changing what it does: where the detail panel opens (On the right or At the bottom, the same switch as View → Detail at Bottom), the zoom, the rows of the sidebar, the labels under compact action buttons, and what the commit list shows. The Detail View pane is gone, and searching Settings for "detail view" still finds its options.
  • A sidebar you can tidy. Library, Smart Views, Filters and Root Folders now collapse from their headers, the way Finder's do, and stay that way. Rows you never use, such as a forge you don't host on or a smart view you don't need, can leave the sidebar from their context menu (Hide from Sidebar) or from Settings → Appearance. There, every row is a tile with its own glyph, beside a live miniature of your sidebar that redraws as you click. Point at a tile and its row lights up; point at a hidden one and a faded row shows where it would come back. All Repositories always stays, and is where a hidden selection lands.
  • Detached HEAD, said plainly. A repository checked out at a commit rather than a branch now shows an orange detached HEAD card with that commit in the Branches tab, and the header says "detached HEAD" instead of git's raw wording. Switch Branch stays available to get back on a branch, and during a stopped rebase the card names the operation.
  • Buttons that say why. While a Pull, a Push or a cleanup runs on a repository, in any window, the buttons that would only be refused are dimmed, with the reason in their tooltip, instead of failing when clicked. Optimize, Deep Clean and Clean up history now take the same lock as every other action.

Bug fixes

  • The months above the contribution calendar in Account now follow the app's language.
  • Refreshing the Overview is no longer silently dropped when a repository turns up mid-refresh, for example when a root folder is added or the watcher finds a new repository: the forced re-fetch carries on where it stopped.
  • Diff All, a comparison in Kaleidoscope, and requests made through the GitHub command-line tool can no longer hang when a helper process leaves something running after it exits.

Under the hood

  • One ChildProcess.finish now waits on every child FinderGit starts (git, the GitHub CLI, ksdiff, blob extraction). Output is drained by dispatch sources, the wait is bounded and cancellable, a stop escalates to SIGKILL, and processes still holding the pipes are stopped with it.
  • Repository ownership is observed per repository, so an action bar redraws only for its own repository's claims, and never for the scheduled background fetch, which yields to any action.
  • The Overview's forced refresh is tracked per repository and settled as each fetch starts, so a drive that supersedes another resumes it instead of cancelling it.
  • Plurals that follow one of two counts are String Catalog substitutions that name their count, and the translation tooling refuses a whole-string plural on a two-count key. The app and both test targets build with no warnings.
  • A test now checks the Settings search index against the controls in the source. It found one setting nobody could search for: Discover nested repositories.

Install

  1. Download FinderGit-0.47.0.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
