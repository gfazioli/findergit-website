FinderGit 0.40.0

Release notes

FinderGit 0.40.0 — dashboards that arrive, pull to refresh, and a What's New that gets out of the way

Highlights

  • The cards on the Overview and the Account arrive rather than simply appear. Each lands just after the one before, its figures roll up from zero and the health ring fills. A refresh you ask for — the toolbar, ⌘R, the header's button or a pull — presses every card and rolls the figures again, so you can watch them being measured, while an update in the background moves them in place. With Reduce Motion on, nothing moves.
  • On macOS 26 and later the cards are made of glass, rounder and with no line drawn around them, over soft light in the colors of the app's icon. The color sits under the glass rather than in it, so a card keeps it when the window is not in front. On macOS 15 they keep their gradient, and are rounder too.
  • On macOS 27, pull the Overview or the Account down to refresh it, as in Mail. It is the same Refresh as the toolbar button and ⌘R: the spinner turns for a moment and then lets the page go, while the work carries on. The Account's header now carries the same Clone from GitHub… and refresh buttons as the Overview's.
  • After an update, a small card in the corner says which version has arrived, and Learn More… opens its notes in the Release Notes window. The notes used to fill a panel in that corner, which a long release could push past the top of the window. Help → Release Notes… still has every release, so the menu item that reopened the panel has gone.
  • The Release Notes window shows each release with a preview of its first change, marks the one you are running as Installed, and sets the notes at reading size. Back and Forward (⌘[ and ⌘]) retrace the releases you looked at, as in System Settings.

Bug fixes

  • A release's unread dot goes when you open it. The Release Notes window measured its dots against a mark taken when it opened, so a dot stayed for as long as the window was up, and every dot went at the next opening, read or not. A release is now read the moment its row is selected, and what the old window showed as read stays read.

Under the hood

The pull is a trigger rather than a hold: it runs the global Refresh in a task of its own and lets go after two seconds at most, or sooner when the work is done. On the Overview it holds on a pending flag raised before your root folders are rescanned, which comes before any repository is read again, and only the pass the refresh asked for clears it.

Text on the cards uses explicit ink levels, because default label colors turn vibrant on glass and lose contrast; by day the rim light is the icon's blue rather than white. The Overview's panels, which a drag re-creates when it reorders them, show at rest rather than landing again.

The window's unread state is a baseline plus the releases read one by one. The baseline has a key of its own, seeded once at launch from the later of the two marks the previous window read, so nothing it showed as read turns unread again, and a fresh install starts counting from the release it installed. The window lists only the releases the running build is or predates.

Install

  1. Download FinderGit-0.40.0.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel). Pull to refresh needs macOS 27, and the glass cards macOS 26.
