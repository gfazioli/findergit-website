FinderGit 0.77.0

Release notes

FinderGit 0.77.0 — Long lists open at once, numbers you can find, and who can see a repository

Highlights

  • Long lists open at once. Opening a card on a repository's Overview that holds many items — Tags, Issues, Pull Requests, Branches — froze the window, and closing it froze it again. Now a card builds only the rows on screen: in our tests, on a repository with 2,393 tags, the Tags card held the window for minutes, and now opens in under a second; Issues and Pull Requests open and close in a few hundredths of a second.
  • Issue and pull request numbers you can find at a glance. Each #number is now a tag in the color of its state — green while open, purple once closed or merged, red for a pull request closed without merging, gray for a draft — every tag as wide as the list's widest number, so the numbers line up in a column.
  • Public, Private or Internal. A repository's Overview now says who can see it on its forge, beside how alive it is, and a lock marks a repository not everyone can see in the file browser, the repository list and the Overview's lists (a public one carries nothing, since most are). It comes with the issue, pull request and star counts FinderGit already reads, in the same request, from GitHub, GitLab and Codeberg.
  • Workbench, a new Profile Card look. A Home Computer family joins the looks: Workbench draws your card as the desktop of a late-1980s 16-bit home computer, in its four colors — a white screen bar, every panel a window with an orange title bar and its gadgets, bevelled figures, your photo in the four colors and copper bars along the bottom, every letter monospaced. The glancecard editor offers it too, as a card that reads the same on GitHub's light and dark themes.

Bug fixes

  • An issue or pull request number above 999 was written with a thousands separator in some languages (#1.234 on an Italian Mac).

Under the hood

  • An open card's panel left its scroll view with no height until it had measured its section, and the deck lays a panel out at its ideal height, so in that first pass every row was "on screen" and a lazy list built them all (700 of 700 in a new test); it now always has a bound. The Issues, Pull Requests and Branches lists are lazy too.
  • The Tags list asked, for each tag, whether this clone has it with a search of the whole tag list, quadratic in the number of tags; the store now keeps the names as a set.
  • The repository's visibility comes from GitHub's GraphQL visibility, GitLab's project visibility and Forgejo's private and internal flags; Bitbucket's counts call doesn't carry it.
  • The glancecard editor writes glancecard v0.8.0, the release that brought the Workbench, whenever the Workbench is picked.

Install

  1. Download FinderGit-0.77.0.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
