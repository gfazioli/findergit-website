FinderGit 0.36.0

Release notes

FinderGit 0.36.0 — The tabs say what is waiting inside them

A small release with one idea in it: a repository should tell you how much is open on it before you go looking.

Highlights

  • The Issues and Pull Requests tabs carry their open count. The number sits on the tab itself, in that tab’s own colour, so selecting a repository answers “is there anything for me here” without a click. It is the forge’s own count of what is open — the same number the Issues and PRs columns already show in the list, read from the same place, so for a repository on screen it costs nothing extra to ask.

  • A tab with nothing open carries no badge, which is the convention the sidebar’s smart views already use: a row you have nothing to do about stays quiet. Neither does a forge that keeps no such count — Bitbucket retired its issue tracker, so its Issues tab stays bare rather than claiming a zero it was never told.

  • Refresh in either tab now refreshes the number too. The listing and the count are read from different places, so refreshing one used to leave the other where it was: two counts of the same thing, disagreeing, one of them just updated.

Fixed

  • A repository whose remote could not be read for a moment — a lock file left behind by another git action is enough — was written off for the rest of the session: no counts anywhere, and no refresh could bring them back. Refresh from the Issues or Pull Requests tab now asks again instead of trusting that verdict.

Under the hood

The badge reads the same per-repository store as the file browser’s Issues/PRs columns rather than counting the rows the tab happens to have loaded. Two reasons: the tab’s listing is paginated and the count is not, so counting rows would under-report a busy repository; and one store means the badge and the column cannot drift apart. They still present zero differently, and deliberately — a column with a heading needs a cell, a tab is quieter without one.

The warm-up that fetches a count when you select a repository waits 400 ms first and is keyed on the selection, so travelling through a list with the arrow keys cancels it before anything is asked. The Fleet view hosts the same panel and has no counts columns of its own, so without that wait every row you passed through would have cost a remote lookup and a forge call, against a store that deliberately enforces no concurrency cap because it was written for a cadence this caller does not have.

One layout idea was built, photographed and thrown away: letting the tab drop its title when the strip runs short, so a count never sits beside an ellipsis. In a 900-point window with the sidebar collapsed it dropped the title while every other tab still showed its name in full — inside a horizontal stack a child is offered its share of the width, not the room actually left over, so the fit test was answering a question about a width nobody was short of. The badge now truncates like the other eight tabs do, which is at least predictable. The trap is written next to the code that would have used it.

Install

Download the DMG below, drag FinderGit to Applications, and open it. The app is signed with an Apple Developer ID and notarized by Apple, so no Gatekeeper bypass is needed. Existing installs update themselves.

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
