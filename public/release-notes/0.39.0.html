FinderGit 0.39.0

Release notes

FinderGit 0.39.0 — your own AI key, a whole changeset in Kaleidoscope, and the file that made your repository heavy

Highlights

  • Commit messages can be written by a provider of your own, under your own key. Settings → AI keeps the free built-in mode as the default — nothing to set up, nothing changes — and offers the other half beside it: your key, kept in the macOS Keychain under an entry of its own, with the diff going straight from your Mac to the service you picked instead of passing through FinderGit at all. A server running on your own Mac needs no key, and nothing leaves the machine. The key is checked before it is stored, so one that would be refused never gets saved — and when the check cannot reach a verdict, the status line says the key was saved unconfirmed rather than claiming more than it knows.
  • Every change in a repository can go to Kaleidoscope as one changeset, instead of a tab per file. Diff All sits at the top of the file list on the Unstage tab and sends staged and unstaged changes together; filter the tab to a directory and only that directory goes. Every comparison is pinned to the same commit, so a commit landing while the files are being prepared cannot mix two baselines into one review. What cannot be sent — a directory, a submodule, a file git will not hand over — is listed underneath with the reason, rather than quietly missing from the changeset.
  • A heavy repository can now name the file responsible. Largest objects in history lists the twenty biggest objects with the path each one was stored under — including files deleted from your working tree years ago, which is exactly why you could never find them by looking at your folder. An object sitting under a top-level folder your checkout does not have is flagged: that is the signature of a clone that swallowed a larger upstream. The Overview does the same job one level up, separating a repository that is bloated from one that is merely big — a monorepo is legitimately gigabytes, while a fork whose history swallowed one weighs the same and is a mistake.
  • Removing that history for good comes as a runbook, not a button. Show the rewrite runbook… gives you the exact commands for dropping the paths you tick, run against a fresh clone rather than your own folder — taken from the remote where there is one, so a branch that was published but never checked out here is rewritten too. It opens with what it costs, before a single command: every commit from the first changed one onward gets a new identity, everyone else has to clone again, and open pull requests point at commits that no longer exist. FinderGit never runs them, on purpose — a rewrite cannot be undone and its blast radius reaches every clone, so it belongs behind a command you read before you run it.
  • Every release the app carries is readable in one window. Help → Release Notes… lists them all, newest first, with the ones you have not read still marked — so an update that arrived while you were busy can still be caught up on, instead of leaving with the panel you dismissed.
  • Two windows can no longer act on the same repository at once. Each window kept its own idea of what was running, so a fetch in one and a pull in the other could reach the same folder together. The claim is app-wide now and follows the repository rather than the window, worktree and tag actions included — and a scheduled fetch steps aside for you instead of refusing you.

Bug fixes

  • An action you stop no longer waits for ever. A git process can hold its output open after it has been told to finish; the drain is bounded now, and what will not let go is stopped rather than waited on. git’s last bytes are kept either way, so an error message is not lost to the cancellation that revealed it.
  • The Overview summary follows a change made anywhere — in another window, or outside FinderGit altogether — rather than keeping the counts it had when you opened it.
  • The What’s New panel keeps its own header. It is an overlay that grows upward, so a long entry pushed the version label and the close button off the top of the window. It scrolls now. The 0.38.0 entry was long enough to hit this at every window size, which is why nobody reading it saw where it started.
  • The new-branch sheet acts on the commit it showed you. It pins the commit it resolved when it opened, keeps the name you typed when git refuses, and stays open on that refusal instead of discarding the work.
  • Two labels read as English grammar in the other three languages. A plural rule cannot head a sentence outside English, and the AI tab and the Release Notes label had drifted from the copy they describe.

Under the hood

Two more nets run on every build, and both exist because a translation can be present and still wrong. One fails when a What’s New bullet does not resolve in all four languages; the other fails when a string is merely present in a .lproj rather than translated — a distinction no coverage figure can make, because a key copied from English counts as covered.

The AI key is stored under a Keychain namespace of its own rather than the forge’s, since a query without an account matches any item under the same server. The providers are not one dialect: what each accepts differs in shape, and the key itself is optional for a server running locally.

A path git cannot print whole is no longer treated as a removal target in the rewrite runbook — a newline inside a path truncates the record and would otherwise name a different file than the one you ticked.

The concurrency warnings this cycle introduced are cleared, and the suite stands at 863 cases.

Install

  1. Download FinderGit-0.39.0.dmg
  2. Open the DMG and drag FinderGit into Applications
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
