Release notes

FinderGit 0.34.0 — every action says how it went, and keeps saying it

Two things ship together here, and they are halves of one idea: an action you start should tell you how it ended, and it should still be telling you when you have moved on.

Highlights

  • Acting on many tags at once now shows its progress. A bar says how many are through and which tag is in flight; each row takes its own outcome as it lands — a green check, a red mark, or "not attempted" for the ones a Stop never reached. Before this, deleting twenty tags looked exactly like the app doing nothing, and the only evidence it had happened was that the list was shorter afterwards.

  • A bulk run survives leaving it. It always kept going when you switched tab or repository — what is new is that it is still there to tell you where it got to when you come back, instead of having quietly finished into an empty room.

  • A run you stopped says what it does not know. A tag whose deletion had already been handed to git is reported as exactly that: not a success, not a failure. It is the one you may have to check by hand, and calling it either would be a guess. When a delete-everywhere stops between its two halves, it says which half went through.

  • Every action now reports itself, in one place. A card appears in the corner when a fetch, a pull, a push, a commit, a stage, a checkout, a stash, a tag action or a worktree action finishes — carrying the repository's name and, when something failed, git's own words. Actions that had never reported anything at all are in there too: deleting a single tag from its row, creating a worktree, clearing away stale ones.

  • Failures wait for you; nothing else does. A card leaves on its own after a few seconds, and nothing ever piles up demanding to be dismissed. But a failure stays unread behind the new bell in the toolbar until you open it, so the one thing you needed to see is the one thing that cannot quietly disappear. A success does not light the badge, and neither does an action you stopped yourself: it means "something needs you", not "something happened".

  • The Activity panel is the session's record. Newest first, failures still carrying git's message, with the repository each belongs to. The same outcome arriving repeatedly folds into one row with a counter rather than filling the list, and a bulk run across many repositories files one summary instead of one row per repository.

Under the hood

The outcome record is an app-level store rather than view state, and that is the whole design: an action outlives the view that started it, so a card owned by the panel that started it disappears exactly when the user goes to look at something else. The countdown timers live with the state for the same reason.

Cards are deliberately transient and the badge is not. A stack of cards that accumulates until dismissed gets cleared reflexively and unread, which fails the one thing such a surface is for; what cannot be lost is the unread count behind the bell. Which of the two carries a given outcome is decided per event: anything you are demonstrably already watching goes to the record and raises no card, and the automatic refresh — fired on a timer and on every file-system event — is not recorded at all.

Reading the panel marks read only the rows that were actually on screen, at the occurrence they were on screen at. Both halves of that sentence are load-bearing: a list is longer than its viewport, and a failure that repeats after you scrolled past it is a new occurrence of something you have not seen.

The bulk tag run holds a monotonic ownership token, because a cancelled run keeps draining its queue to report each remaining tag as not attempted, and without an owner those late writes landed on the run that had replaced it.

Two localisation traps were worth the rework. Composing an action's name into "%@ failed" reuses keys that are button labels, whose translations are imperatives — it would have read "Metti in stage non riuscito" in Italian and nothing wrong at all in English. And with real nouns the genders are mixed, so one key cannot carry both échoué and échouée: putting the participle first, behind a colon, makes it modify nothing and stay invariable in all four languages.

Install

Download the DMG below, drag FinderGit to Applications, and open it. The app is signed with an Apple Developer ID and notarized by Apple, so no Gatekeeper bypass is needed. Existing installs update themselves.

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
