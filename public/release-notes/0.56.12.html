FinderGit 0.56.12

Release notes

FinderGit 0.56.12 — branches that share a name with a tag

Bug fixes

  • A branch with the same name as a tag now behaves like a branch. With a branch and a tag both called main, the branch list showed heads/main, and switching to it left the repository on a detached HEAD; renaming or deleting it failed. It now appears under its own name and switching keeps you on it. Merging it, rebasing onto it and starting a new branch from it use the branch's commit, never the tag's.
  • History cleanup always protects the branch you are on. When a tag shared its name, the checked-out branch could be offered for removal, and the check meant to refuse it did not recognise it. It is now kept out of the candidates and refused.
  • The Agents page reads your repositories with the git you chose in Settings from its very first scan. The first scan after launch used the system git, and what it reported went to the system log instead of the Activity feed.

Under the hood

  • Each branch now carries two spellings: its name, for checkout, rename, delete and the match with git status, and the unambiguous revision git prints with %(refname:short) (heads/main when a tag shadows it), for merge sources, rebase upstreams and start points. The current branch is read from the full symbolic-ref, not its shortened form.
  • The Agents host settings (git and the Activity feed) are set at launch rather than when the page appears, since the dashboard's own first scan starts before the page's appear handler runs; the git path follows Settings when it changes.

Install

  1. Download FinderGit-0.56.12.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
