FinderGit 0.76.0

Release notes

FinderGit 0.76.0 — Programs a repository runs, held until you allow them

Highlights

  • Programs a repository runs, held until you allow them. A repository's own git configuration can name programs that git runs for it: hooks, filters, a diff tool, an SSH command, a credential helper. git never copies them with a clone, but a repository unpacked from an archive or copied from another Mac keeps them, and FinderGit runs git without a click: a fetch at launch and on the auto-fetch timer, a status whenever a file changes. When a repository you add configures any, its Trust card lists them, and until you allow them FinderGit doesn't fetch it on its own, and what it reads on its own (the status, the diff of a file you select, the Overview's size check) runs none of them. A Fetch, Pull, Push or Commit you click runs them as usual. Allow these programs takes one click; if they change later, the automatic fetch is held again and what is new is marked. Repositories already in your folders when you update stay allowed as they were.

Bug fixes

  • A GitHub token that works but lacks one permission, or that hit GitHub's rate limit, was called rejected, and you were sent to replace a token that was fine. Now a missing permission is named when GitHub says which (otherwise you're asked to check that the token covers the repository and its owner), fork sync says it needs Read and write on Contents, and a rate limit reads as a rate limit, also when you save a token. The file browser's counts and the Actions and Security cards then wait for your Refresh instead of asking again each time they appear, and a refused read keeps the Checks and Dependabot figures already shown.

Under the hood

  • The gate reads a repository's own git configuration with git config, which starts no program, keeping only what the repository itself sets (an included file counts, and so does every submodule's own configuration), and lists its hooks without running them. A held repository's reads run with its hooks pointed at /dev/null, its filter drivers emptied and --no-ext-diff --no-textconv: a status that refreshes stale stat data rewrites the index, and git then runs the post-index-change hook. Your global configuration is yours: a globally installed Git LFS or a keychain credential helper holds nothing.
  • Every git call FinderGit makes now carries -c log.showSignature=false beside core.fsmonitor=false: when a repository sets log.showSignature, git runs its gpg.program on any git log over a signed commit, and FinderGit reads the newest commit as soon as a repository is selected.
  • The Actions card's beam now counts its laps in UndologUI 0.2.0 rather than in a timer of FinderGit's own. The MIT license notice of the code the beam is ported from ships inside the app, so the About window drops its Open-Source Licenses link.
  • Six test suites now compare the app's types on the main actor, ready for the Swift 6 language mode.

Install

  1. Download FinderGit-0.76.0.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
