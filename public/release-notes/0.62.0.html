FinderGit 0.62.0

Release notes

FinderGit 0.62.0 — issues and pull requests that read like the web

Highlights

  • A thread reads the way it does on the web. Review bots, and plenty of people, write their comments with HTML inside the Markdown: collapsed sections, definition lists, tables, line breaks, pictures with a light and a dark variant. FinderGit used to print all of it as tags, forty lines of <details> and <br> before the first word. It now draws it: bold, links, headings, lists, tables and quotes come out as what they mean, and code is left exactly as written.
  • Collapsed sections are folds. A collapsed section is a row with a chevron: click to open, click again to close. Folds nest, start open when the author said so, and a long description counts a closed fold as one row, so Show more appears only when there is more to show.
  • Callouts carry their title. > [!NOTE], Tip, Important, Warning and Caution print their heading, in your language.
  • Copy link is where you look first. In an open issue or pull request the actions moved to the top, Copy link filled and first. Under a discussion they are repeated, so the end of a long thread has them too.
  • A link button on every row. Each row of the Issues and Pull Requests tabs has its own link button: the address is one click away without opening the thread, and the button confirms the copy.
  • Right-click an issue or a pull request. Open it on the web, or copy its link, a Markdown link ([#12 Title](…)), its title, its number and, for a pull request, the name of its branch.

Bug fixes

  • Links in a thread open web and mail addresses only. A thread is written by anyone who can open an issue; a link that names a file or another app is no longer followed.
  • A comment cannot be written to stall the window. A table declared thousands of columns wide is a few kilobytes of text and millions of cells on screen. A table past 50 columns or 2,000 cells is now shown as plain lines, and nesting and the number of folds in one comment are capped.
  • The avatar of whoever opened an issue or pull request shows in its preview; on GitHub it was a grey disc.
  • A comment that quotes <!-- inside code no longer loses everything after it.
  • Relative links in a thread resolve against the thread's own page.

Under the hood

  • The conversion lives in the framework: a line lexer that knows code from prose (fenced, indented, in backticks, inside a quote or a list item) and a stack builder that turns the allowed tags into Markdown blocks and folds. A tag it does not know, such as Array<String>, is left as text.
  • It is bounded on hostile input: look-ahead has a budget, nesting stops at 40 levels and quotes at 8, a comment holds at most 200 folds, link definitions copied across folds have a size budget, and the table limits apply to HTML and Markdown tables alike. Bodies of 56 to 65 KB written to be slow or large convert in about a tenth of a second at worst.
  • A reference-style link finds its definition on the other side of a fold: each block is given the definitions it uses.
  • Images in a thread are still never fetched from the network.
  • A thread's body is converted when its text changes, not every time the panel around it redraws.

Install

  1. Download FinderGit-0.62.0.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
