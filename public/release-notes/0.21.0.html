FinderGit 0.21.0

Release notes

Highlights

🔍 Discover nested repositories

FinderGit can now count repositories nested inside another repository. If a folder you track is itself a Git repo and holds independent clones inside it — a collection of related projects that also happens to be under version control — those inner repos used to be invisible to your counts, Smart Views, and Overview. Now they're all counted.

  • Off by default — scanning still stops at the outermost repository on each path unless you opt in. Turning it on can meaningfully change your totals (one workspace jumped from 7 to 63 repositories).
  • Toggle it three ways: Settings → General → File Browser, the View menu (⌘⇧N), or a toolbar toggle next to Refresh. The Overview subtitle shows when nested counting is on.
  • Stays bounded by your scan depth and excluded folders. Submodules are never counted.

✨ A clearer Overview header

The Clone from GitHub and Refresh actions are now grouped into one prominent control cluster — easier to spot at a glance.

🌍 Fully localized

All the new text is translated in Italian, French, German, and Spanish, including the What's New notes.

Under the hood

  • The root-folder scanner can now descend past a discovered repository to find nested working copies, still bounded by the configured scan depth and excluded-folder list. Submodules (a .git file rather than a directory) are excluded by construction.
  • All entry points (Settings, View menu, toolbar) drive a single centralized rescan trigger, so discovery re-runs exactly once no matter where you flip the toggle.
  • Repository discovery now publishes its results only when they actually change, avoiding redundant view rebuilds.

Install

Download the DMG from the release below, drag FinderGit to your Applications folder, and launch it. First launch needs no Gatekeeper bypass — the app is signed with a Developer ID and notarized by Apple.

Requirements

macOS 15 (Sequoia) or later. Universal binary (Apple Silicon + Intel).
