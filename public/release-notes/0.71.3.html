FinderGit 0.71.3 — Other Hosts, a filter of their own

Bug fixes

  • A repository on a server FinderGit doesn't read has a filter of its own: Other Hosts. A clone from a company Bitbucket, a self-hosted GitLab or a Gitea was counted under Local Only in the sidebar, while its Overview, since 0.71.2, named the server and its footer read origin/master. It now sits under Other Hosts, between Codeberg and Local Only, with the same server glyph the Overview uses. git works there as anywhere else: fetch, pull, push and the ahead/behind counts. Issues, Pull Requests and Stars stay empty, since there is no forge behind it that FinderGit reads.
  • Local Only keeps the repositories with no remote, or with one that is a folder on this Mac, such as a bare repository beside the clone.

Under the hood

  • The store that reads each repository's origin kept "no origin" and "an origin on a host FinderGit doesn't read" in one set; it now records the sidebar filter each one lands in. A Refresh moves a repository between the two, and out of both when its origin moves to a forge.
  • Re-reading an unchanged repository no longer redraws the sidebar's counts: removing a key that was not there still notified the observers of an @Observable dictionary, and that removal is now skipped.

Install

  1. Download FinderGit-0.71.3.dmg
  2. Open the DMG and drag FinderGit into Applications (or open it from there, and it offers to move itself)
  3. Launch normally — the app is signed with an Apple Developer ID and notarized by Apple

Requirements

macOS 15 or later. Universal binary (Apple Silicon and Intel).
